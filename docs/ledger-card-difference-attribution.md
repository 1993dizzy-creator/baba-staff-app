# 카드 정산 차액의 거래 이력 보정 설계

월마감 snapshot은 matched 정산의 연결 매출일을 기준으로 차액을 재배분한다. 기존 `card_settlement_difference` 거래와 카드 정산대기 계좌 movement는 그대로 둔다. 입금월에 적힌 기존 비용과 매출월 귀속액의 차이는 snapshot의 `카드 정산 차액 · 매출월 귀속` 조정값으로 표시한다.

원장 transaction 자체를 월별로 재분류하려면 별도 후속 migration이 필요하다. 정산 건마다 다음을 하나의 트랜잭션에서 수행한다.

1. 정산 상태가 `matched`이고 연결 line의 gross 합계가 `matched_gross_amount`와 같은지 검증한다. 월별 차액은 gross 비율로 계산하고 0.001₫ 잔여는 fractional remainder가 큰 월부터, 동률이면 월 오름차순으로 배분한다.
2. 입금월 원본 비용 거래를 변경하지 않고, 같은 인식월에 음수 경제효과의 child transaction을 추가한다. 카드 정산대기 movement는 추가하지 않는다.
3. 각 매출월에 배분된 차액을 양수 expense recognition transaction으로 기장한다. 이 거래에도 movement를 추가하지 않는다. 입금월 원본 movement만 실제 카드 정산대기 감소를 나타낸다.
4. `source_key`에 정산 ID와 매출월을 포함하고 중복 투영을 거부한다. 원본, 역분개, 재기장 ID와 월별 배분을 감사 snapshot에 남긴다.
5. 취소 시 기존 정산 취소 RPC가 만드는 입금·차액 역분개에 더해 월별 재기장을 각각 역분개하고, 원본 비용에 붙은 투영 역분개도 상계한다. 이 부분은 기존 취소 RPC와 함께 교체해야 한다.

기존 matched 정산에 대한 보정은 해당 매출월과 입금월의 장부가 쓰기 가능한 상태일 때만 수행한다. 예를 들어 8월 입금 정산에 7월 매출이 포함되고 7월이 마감된 상태라면, 7월을 안전하게 재오픈하지 않고 7월 transaction을 생성해서는 안 된다. 대상 월의 마감 상태와 보정 대상 건수를 확인한 뒤 별도 승인 절차에서 실행한다. 이 문서는 실행 SQL이나 운영 데이터 변경을 포함하지 않는다.
