보류 결정 이유

현재 근태 정책의 조퇴 허용시간은 90분이다.

일반적인 조기 마감은 이 범위로 대부분 처리할 수 있으며, 조퇴 허용시간보다 훨씬 일찍 매장을 닫는 상황은 수개월에 한 번 있을까 말까 한 희귀 사례다.

희귀 사례를 위해 등록·수정·취소 UI, API, RPC, 감사 이력, 운영시간 revision 충돌 검증을 추가하면 구현 및 유지 비용이 실제 효용보다 커진다.

따라서 예외 상황은 owner/master가 관리자 권한으로 해당 직원의 근태를 직접 확인하고 정상처리한다.

현재 운영 정책

일반적인 조기 마감은 조퇴 허용시간 90분 범위에서 처리한다.

그보다 이른 예외 마감은 owner/master가 근태 상세에서 직접 정상처리한다.

관리자 정정 사유와 기존 감사 로그를 남긴다.

매장 운영시간 revision은 변경하지 않는다.

영업일 마감 03:00은 변경하지 않는다.

POS·재고·Cron 스케줄을 변경하지 않는다.

과거 근태를 일괄 재계산하지 않는다.

store_business_day_overrides에 운영자가 직접 SQL로 기록하지 않는다.

개발 시 주의

기존 테이블과 Shadow 분기를 보고 운영 기능이 있다고 판단하지 않는다.

별도 승인 없이 특별 조기마감 UI·API·RPC·Migration을 추가하지 않는다.

사용자 화면에 상시 특별 조기마감 안내나 입력 진입점을 추가하지 않는다.

현재 사용 기록이 없다는 이유로 기존 테이블과 분기를 즉시 삭제하지 않는다.

전체 DB·레거시 정리 작업에서 유지 또는 제거를 다시 판단한다.

관련 코드를 수정할 때는 기존 Shadow 동작을 깨뜨리지 않도록 한다.
