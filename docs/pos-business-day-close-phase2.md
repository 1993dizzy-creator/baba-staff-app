## Manual API flow

POST /api/admin/sales/close accepts businessDate, reclose (boolean), and optional
expectedSourceFingerprint (64 lowercase hex). All other body keys, including
actorUsername/id/role/syncRunId, are rejected. Actor identity comes exclusively
from getAuthenticatedActor and the trusted baba_session server contract.

Server checks actor role and configured close time; calls the existing POS
sync-to-sales endpoint with force:true, businessDate, limit:100 and a server-only
POS_ADMIN_SECRET; requires HTTP success, ok:true, no skipped response, no limit
warning or skipped/unavailable payloads, and the persisted source_complete run.
It then reauthenticates, reloads the shared canonical source, verifies a reclose
review fingerprint, and calls sales_close_business_day_after_sync_v1. That
wrapper takes phase-1 month/day keys and SHARE source locks, rejects any running
POS sync and unknown/incomplete/stale run, then delegates to the unchanged
sales_close_business_day_v1. Its card settlement/month/manager/no-op contracts
remain authoritative. Ledger projection and close insert are phase-1 atomic.

Owner/master/manager initially close; only owner/master reclose. Past business
dates or configured closeAt after-hours only. No early-close override exists.
The original single POS latest-data button still sends force:true to its existing
API. It is disabled while close is running; date changes are likewise blocked
while that action is running.

## Scheduled final flow

GET /api/cron/sales-close-final authenticates with the existing timing-safe
CRON_SECRET Bearer or x-cron-secret contract. Missing secret is fail-closed.
Configured business-time adapter resolves previous business date; settings
fallback and execution before cutoff are refused. Runtime username pos actor
must be active, login enabled, and owner/master; no numeric ID is hardcoded.

A private ten-minute date lease serializes overlapping network jobs. The latest
qualifying run must match businessDate, source=cukcuk, status=success,
source_complete=true and error_message=NULL; start >= configured cutoffAt,
start < cutoffAt+24h, finish >= start, finish <= now and finish >= now-30min.
A pre-cutoff/recent-other-date/old-unknown-completeness run cannot authorize close.
If no eligible run exists, exactly one force refresh is attempted. Failure
records sync_failed; incomplete response or source mismatch records source_invalid.
Leases release in finally; token-scoped release cannot remove a newer lease.
A crashed job's lease expires, allowing a later retry.

sales_finalize_business_day_v1 requires runtime pos actor and a valid lease;
takes the existing month/day advisory locks, validates run and live canonical
source under SHARE locks and refuses running source sync. It reads the latest
closure FOR UPDATE. No closure: delegate to phase-1 automatic close. Existing
closure: never call generic projection or reclose. Compare authoritative total
and all four buckets, then fingerprints. Results:
verified_unchanged / metadata_changed_only / financial_drift.
Automatic close and check insert share one transaction. Source/projection
exceptions roll back all Ledger/close writes; workflow then records source_invalid
through a separate failure-only finalize call. A month-closed automatic close
failure is also persisted as source_invalid with closeResult detail.

## History schema and idempotency

Actual local migration SQL:

```sql
create table public.pos_sales_business_day_close_checks (
  id bigint generated by default as identity primary key,
  business_date date not null,
  closure_id bigint null references public.pos_sales_business_day_closures(id) on delete restrict,
  checked_at timestamptz not null default now(),
  check_type text not null check (check_type in ('scheduled_final', 'manual_refresh')),
  result text not null check (result in ('verified_unchanged', 'metadata_changed_only', 'financial_drift', 'sync_failed', 'source_invalid')),
  sync_run_id bigint null references public.pos_sales_sync_runs(id) on delete restrict,
  closed_fingerprint text null check (closed_fingerprint ~ '^[0-9a-f]{64}$'),
  current_fingerprint text null check (current_fingerprint ~ '^[0-9a-f]{64}$'),
  closed_total numeric(16,0) null check (closed_total >= 0),
  current_total numeric(16,0) null check (current_total >= 0),
  total_delta numeric(16,0) null,
  closed_buckets jsonb null check (jsonb_typeof(closed_buckets) = 'object'),
  current_buckets jsonb null check (jsonb_typeof(current_buckets) = 'object'),
  bucket_delta jsonb null check (jsonb_typeof(bucket_delta) = 'object'),
  detail_snapshot jsonb not null default '{}'::jsonb check (jsonb_typeof(detail_snapshot) = 'object'),
  idempotency_key text not null unique check (idempotency_key ~ '^[0-9a-f]{64}$'),
  created_at timestamptz not null default now(),
  constraint pos_sales_close_check_result_evidence check (
    result in ('sync_failed','source_invalid') or (
      closure_id is not null and sync_run_id is not null and closed_fingerprint is not null
      and current_fingerprint is not null and closed_total is not null and current_total is not null
      and total_delta = current_total - closed_total and total_delta is not null
      and closed_buckets is not null and current_buckets is not null and bucket_delta is not null
    )
  )
);
create index pos_sales_close_checks_latest_idx
  on public.pos_sales_business_day_close_checks(business_date, checked_at desc, id desc);
create index pos_sales_close_checks_closure_idx on public.pos_sales_business_day_close_checks(closure_id);
create index pos_sales_close_checks_run_idx on public.pos_sales_business_day_close_checks(sync_run_id);
alter table public.pos_sales_business_day_close_checks enable row level security;
revoke all on table public.pos_sales_business_day_close_checks from public, anon, authenticated, service_role;
revoke all on sequence public.pos_sales_business_day_close_checks_id_seq from public, anon, authenticated, service_role;
grant select on table public.pos_sales_business_day_close_checks to service_role;
create trigger pos_sales_close_check_immutable before update or delete on public.pos_sales_business_day_close_checks
for each row execute function pos_sales_close_private.immutable_closure();
create trigger pos_sales_close_check_no_truncate before truncate on public.pos_sales_business_day_close_checks
for each statement execute function pos_sales_close_private.immutable_closure();
```

Idempotency key hashes the fixed ordered tuple: business date, scheduled_final,
closure ID, sync run ID, current fingerprint and result. UNIQUE + ON CONFLICT
DO NOTHING preserves immutable timestamps/history and returns the existing ID.
Check UPDATE/DELETE/TRUNCATE are blocked. No existing closure or decision history
is updated/backfilled. pos_sales_sync_runs gains nullable source_complete;
legacy NULL is deliberately unknown. Existing sync behavior/response stay intact.

## Permissions

New public claim/release/finalize/after-sync functions: SECURITY DEFINER,
owner postgres, search_path pg_catalog, public; REVOKE PUBLIC/anon/authenticated/
service_role followed by GRANT EXECUTE service_role only. Private require_final_actor:
SECURITY INVOKER, same fixed path, postgres owner, no public-role EXECUTE.
Check table: RLS enabled, SELECT service_role only, no client direct writes.
Private lease table/schema deny all public roles. Lease is orchestration only,
not a projection capability or session bypass. Phase-1 functions are preserved.

Status GET /api/admin/sales/close-status allows owner/master/manager/leader under
server session; staff denied. Current daily page retains its existing leader
redirect. Read returns current totals/fingerprint, normalized latest closure
and actor (automatic displayed as localized System), latest relevant check,
financial deltas, close eligibility, final sync info and actual Ledger projection
comparison to the closed rows/movements. Receipt/payment/detail snapshots are
not returned. A check for an older revision is omitted after reclose.

## Final preflight corrections

The unapplied migration filename stays 20260912112349_add_pos_business_day_close_checks.sql.
The already-applied phase-1 migration is unchanged.

source_complete is true only for success, raw CUKCUK response below limit,
zero detail skips, zero unavailable payment snapshots, complete persisted receipt
IDs/payment snapshots, successful shared counted/paginated canonical day-source
validation, no partial work, and NULL error_message. Limit hit, unknown source,
reconciliation/bucket mismatch, failed or partial work yields false. Running can
be NULL; failed completion and expired-running cleanup explicitly store false.
finishSyncRun additionally gates true on error_message=NULL, preventing contradictory
application writes. No strong DB constraint is added to legacy runs: NULL remains
unverified and cannot authorize manual or final close.

The final workflow reads the latest cutoff-era attempt for diagnostics, then applies
all eligibility conditions. A legacy success with NULL completeness triggers exactly
one force refresh; only the newly complete eligible run authorizes finalize.

No-closure automatic close returning month_closed now records result month_closed,
not source_invalid. Existing closed-month closures remain compare-only. Other blocked
close statuses retain source_invalid with exact blocker failureCode/closeResult.
KO/VI use the existing translated month-close message for this new result.

Failure detail_snapshot contains businessDate, cutoffAt, syncRunId, failureCode,
reason, finalSync (eligibility, run ID/status/completeness/lookup failure), retryExecuted,
retryFailureReason, and closeResult. Only known diagnostic codes are generated;
upstream raw errors, tokens and secrets are excluded. SQL guarantees required keys
even when failure input has no source/fingerprint/amount evidence.

Native PostgreSQL verifies check INSERT failure rolls back the already-executed
automatic closure, Ledger and audits, expiry/reclaim, obsolete token rejection,
lease/check duplication races, table RLS/SELECT-only grants, private access denial,
fixed function paths, PUBLIC/anon/authenticated revokes, migration rollback (including
source_complete), and preservation of phase-1 function definitions/ACLs.
