# Shared inventory editor verification (2026-10-10)

Changed: components/inventory/InventoryItemEditor.tsx (new shared edit-only component), components/inventory/InventoryPageContent.tsx, app/(protected)/inventory/snapshots/page.tsx, and five regression test files (inventory-category-labels, inventory-part-ui-contract, inventory-snapshot-name-sync, inventory-mutation-session-auth-policy, inventory-snapshots-browser).

Snapshot banner and history edits now share the full item editor with /inventory. Both language names, existing photo, supplier, category, part, code, quantity, price and detail fields use the shared edit handlers. Missing names receive focus without copying another language into the empty field. Saving refreshes warnings; failures preserve drafts. Opening and write locks prevent duplicate requests. Photo upload keeps draft names and refreshes the expected version. Runtime language changes swap name drafts with their language labels.

Performance: formerly snapshots dynamically imported the entire InventoryPageContent (299964 source bytes); now they import InventoryItemEditor (57981 source bytes, 81% smaller source). This is a source/module-scope comparison, not a measured production bundle or transfer-byte comparison. Selected-item GET count remains 1 per snapshot modal opening (not improved from the prior selected-only implementation); there are no bootstrap/list/recent-log/snapshot requests while opening the editor. /inventory reuses its loaded selected item and suppliers with 0 additional selected-item GETs. Latest local dev first-open timings across the four browser combinations were approximately 0.38?0.88 seconds; no comparable pre-change latency measurement exists.

Validation: 232 regression tests passed. Browser suite passed KO/VI x desktop/mobile with all API requests intercepted: banner date, missing-name focus, photo and supplier presence, photo upload and draft preservation, success/failure, duplicate-write suppression, warning removal, history editing, cancel, scroll/filter retention, historical-date selection, canceled #613 exclusion, unchanged accounting payload, /inventory shared edit hydration with no additional item fetch, and existing quick-save comma/caret/numeric payload regression. Mock selected-item, photo and edit responses retain the actual API envelope (PATCH edit returns ok/mode/ledgerSync, not item data). ESLint: zero errors/warnings for three modified application files. TypeScript: 40 errors matched the previous audit; zero new errors.

Limitations: layout item 3 was explicitly excluded by the request's opening sentence. Existing modal layout, full-width close button and overlay scrolling therefore remain. Production build transfer size and pre-change cold-open latency were not measured. Browser data is mocked, not a production end-to-end test. Existing TypeScript errors remain out of scope. No database/API/SQL changes, production writes, deployments, or Git commands were performed. Ledger, atomic-audit, V2 correction and month-close logic remain on the existing API path and were covered by related regressions.
